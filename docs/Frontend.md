# فرانت فارسی SmartPlanner

## قابلیت قابل استفاده

- ثبت‌نام، ورود، بازیابی نشست پس از refresh و خروج با کوکی HttpOnly و CSRF.
- فهرست، جست‌وجو، فیلتر، ساخت، ویرایش، تکمیل/بازگرداندن و حذف کارها؛ مدت، اولویت، ترجیح زمانی، قابلیت تقسیم و مهلت.
- ساخت، ویرایش و حذف تعهد ثابت با کنترل نسخه.
- انتخاب صریح کارها و وقت آزاد برای پیش‌نمایش یک روز یا هفت روز؛ جابه‌جایی بین روزهای هفته، نمایش کارها و تعهدها در timeline.
- ذخیره و بازکردن برنامه، تغییر نام، جابه‌جایی زمان با فرم قابل‌استفاده با کیبورد، برداشتن بلوک، قفل/بازکردن قفل، Undo/Redo و پیش‌نمایش بازچینی.
- شش ترجیح برنامه‌ریزی، پیام تداخل/نسخهٔ قدیمی، کار جا نشده، حالت خالی و خطای اتصال.
- راست‌به‌چپ، فونت محلی وزیرمتن، منوی موبایل، dialog با مدیریت focus، هشدار ترک پیش‌نمایش ذخیره‌نشده و کاهش حرکت مطابق تنظیم سیستم.

فرانت دادهٔ نمایشی یا حساب ساختگی ندارد. داده‌های ساختگی فقط در آزمون‌های mock مرورگر هستند. همهٔ زمان‌ها در منطقهٔ زمانی حساب تبدیل می‌شوند؛ نمایش روز شمسی است ولی کنترل‌های استاندارد ورود تاریخ، میلادی‌اند. ساعت مرورگر مبنای تبدیل زمان حساب نیست. ساعت محلی مبهم/ناموجود در تغییر ساعت رد می‌شود.

## معماری و اجرا

React + TypeScript + Vite در `frontend/`؛ همان API و PostgreSQL موجود. کتابخانهٔ Temporal برای تبدیل دقیق timezone، Lucide برای آیکون‌ها و Vazirmatn از بستهٔ محلی استفاده می‌شوند. هیچ AI، کلید سرویس یا پایگاه دادهٔ جدیدی نیاز نیست. فایل قفل npm نسخه‌های نصب را تثبیت می‌کند.

ساده‌ترین اجرای کل محصول:

```sh
python scripts/init_env.py
docker compose up --build
```

سپس `http://localhost:8000/` را باز کنید. Dockerfile ابتدا فرانت را می‌سازد؛ FastAPI فایل نهایی را از همان origin سرو می‌کند. `http://localhost:8000/docs` همچنان API docs است. Docker Compose کامل در این محیط اجرا نشده است؛ آزمون CI از همان فرانت buildشده با FastAPI واقعی استفاده می‌کند.

توسعه با hot reload، در دو ترمینال و با PostgreSQL توسعه:

```sh
# ریشهٔ مخزن؛ DATABASE_URL را قبلاً برای پایگاه توسعه تنظیم کنید.
export APP_ORIGIN=http://localhost:5173
python -m smartplanner.migrate
python -m uvicorn smartplanner.api:create_app --factory --host 127.0.0.1 --port 8000
```

```sh
cd frontend
npm ci
npm run dev
```

`http://localhost:5173` را باز کنید. Vite مسیر `/api` را به پورت ۸۰۰۰ می‌فرستد. Origin پورت ۵۱۷۳ باید با APP_ORIGIN بک‌اند یکی باشد. سرویس production به build با origin واحد و HTTPS نیاز دارد؛ این تغییر انتشار عمومی انجام نمی‌دهد.

## قواعد ذخیره و خطا

پیش‌نمایش، جابه‌جایی و تغییر قفل تا تأیید ذخیره پایدار نمی‌شوند. شمارهٔ نسخهٔ برنامه/کار/تعهد/ترجیحات همراه تغییر ارسال می‌شود. خطای 409 پیش‌نمایش را از بین نمی‌برد. کنترل نهایی مهلت، قفل و تداخل با سرور است. برای جابه‌جایی بلوک قفل‌شده، ابتدا بازکردن قفل را جدا ذخیره کنید.

شناسهٔ درخواست ساخت کار و تغییر برنامه پس از قطع اتصال در حافظه نگه داشته می‌شود تا ارسال مجدد همان payload تغییر را دو بار اجرا نکند. این شناسه‌ها پس از بارگذاری کامل صفحه باقی نمی‌مانند؛ پس از refresh ابتدا دادهٔ ذخیره‌شده را بررسی کنید. ساخت تعهد هنوز backend idempotency ندارد؛ پس از نتیجهٔ نامشخص، دکمهٔ ثبت قفل می‌شود تا کاربر فهرست را دوباره بررسی کند.

فرانت، تعهدهای جدول را داخل snapshot دستی برنامه کپی نمی‌کند. هنگام save کنترل زندهٔ Step 9 آن‌ها را بررسی می‌کند و هنگام replan سرور دوباره می‌خواند. این کار از دوبرابرشدن تعهد در بازچینی برنامه‌های ساخته‌شده در این فرانت جلوگیری می‌کند. برنامه‌های قدیمی که snapshot تعهدهای ذخیره‌شده را به‌عنوان تعهد دستی دارند ممکن است قبل از بازچینی به اصلاح منبع نیاز داشته باشند.

فهرست‌ها صفحه‌بندی API را کامل می‌خوانند. در هر برنامه حداکثر ۱۰۰ کار انتخاب می‌شود. نمای هفته فعلاً هر روز ساعت آزاد یکسان دارد. برای برنامه‌های ذخیره‌شده محدودهٔ تاریخ ثابت است؛ افزودن کار به برنامهٔ موجود و تنظیم وقت آزاد متفاوت برای هر روز هنوز UI ندارند.

## بررسی و محدوده

طراحی، پیاده‌سازی و خودبازبینی توسط همین دستیار انجام شده‌اند؛ بازبین مستقل استفاده نشده است.

آزمون‌ها:

```sh
npm run --prefix frontend build
cd frontend && npx playwright install chromium && npm test
```

پنج سناریوی mock مرورگر: RTL/موبایل/کیبورد، تلاش مجدد امن، نگهداری پیش‌نمایش پس از رد ذخیره، خطای ورود، جلوگیری از تکرار مبهم تعهد. سناریوی ششم با `E2E_NATIVE=1` و `E2E_BASE_URL` به API واقعی و PostgreSQL آزمایشی وصل می‌شود: ثبت‌نام تا ساخت کار/کلاس، save، حرکت، refresh، Undo/Redo، replan، ترجیحات و خروج. `tests/test_web.py` مسیرهای static و API را بررسی می‌کند. workflow موجود این مراحل را همراه آزمون‌های کامل بک‌اند اجرا می‌کند.

مانده‌ها: AI/ورودی زبان طبیعی، خروجی فایل، رابط فعالیت تکراری، drag-and-drop (جایگزین کیبوردی اکنون موجود است)، انتخابگر تاریخ شمسی بومی، نگهداری draft پس از بستن مرورگر، تست Safari/Firefox و آزمون بار. این نسخه، آماده‌بودن تجاری یا تکمیل همهٔ MVP را ادعا نمی‌کند.
