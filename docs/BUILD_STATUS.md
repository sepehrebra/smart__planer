# وضعیت ساخت — نسخهٔ ۰٫۵

## وضعیت فعلی قدم ششم

- فعالیت‌های تکراری روزانه، هفتگی و روزهای منتخب با تاریخ شروع و پایان اختیاری، توقف، ویرایش و حذف الگو اضافه شد.
- تولید صریح نوبت‌های ۱ یا ۷ روز، کارهای مستقل می‌سازد. هر نوبت در روز محلی خودش پنجره دارد و از مسیر عادی برنامه‌ریزی، ذخیره، ویرایش و تاریخچه استفاده می‌کند.
- انجام، لغو یا حذف یک نوبت به بقیه اثر نمی‌گذارد. تولید دوباره کار اضافی نمی‌سازد و نوبت حذف‌شده را برنمی‌گرداند. ویرایش الگو فقط نوبت‌های هنوز ساخته‌نشده را تغییر می‌دهد؛ نوبت‌های قبلی جدا مدیریت می‌شوند.
- migration شمارهٔ ۴ الگو، ارتباط کار/تاریخ، قید یکتایی حتی برای کار حذف‌شده و کلید خارجی هم‌مالک را اضافه می‌کند. ایجاد و تغییر الگو با کنترل نسخه/شناسهٔ درخواست، و تولید با تراکنش و قفل انجام می‌شود.
- رابط تقویم، AI، خروجی فایل و انتشار عمومی هنوز باقی‌اند. تکرار ماهانه، تکرار تعهد با ساعت ثابت و تغییر دسته‌جمعی نوبت‌های موجود در این قدم ارائه نمی‌شوند.

- تکرار درخواست، محدوده‌های مشترک، تکمیل/لغو/حذف مستقل، تغییر و توقف الگو، نسخهٔ قدیمی، مالکیت و CSRF، رد جعل ارتباط الگو روی کار، شکست بعد از درج واقعی، ذخیرهٔ هفته و Undo بررسی شدند.
- روز کبیسه، روزهای ۲۳ و ۲۵ ساعته، نیمه‌شب حذف‌شده/تکراری، روز کاملاً حذف‌شده، تهران و اختلاف ساعت ۴۵ دقیقه بررسی شدند. درخواست نامعتبر روز یا مدت، کار ناقص ثبت نمی‌کند.
- migration چهارم روی پایگاه دارای نسخهٔ قبلی اعمال شد؛ اجرای دوبارهٔ migration موفق و بدون تغییر بود. پایگاه محلی کاملاً متوقف و دوباره راه‌اندازی شد؛ حساب، کار، برنامه، تاریخچه، رسید، الگو و وضعیت تکمیل/حذف نوبت‌ها باقی ماندند. تولید دوباره نوبت اضافی نساخت.
- بازبین مستقل قرارداد و کد را بررسی و ۱۱ آزمون تقویمی را جدا اجرا کرد. ایراد مسدودکننده‌ای گزارش نشد؛ محاسبهٔ امروز به پس از انتظار قفل منتقل شد.
- اجرای اولیه در PGlite Socket به اشکال نام prepared statement در چند اتصال برخورد کرد. درج حداکثر هفت نوبت به یک دستور دسته‌ای پارامتری تبدیل شد؛ آزمون‌ها سپس موفق شدند. آزمون پایگاه اصلی و هم‌زمانی در GitHub Actions معیار نهایی است.

## محدودیت محیط آزمایش و بررسی GitHub

نصب PostgreSQL معمولی در محیط محلی به محدودیت ساخت کاربر سیستم برخورد کرد. PGlite برای اجرای SQL استفاده شد. در PGlite Socket پس از خطای SQL دارای پارامتر، هماهنگی پاسخ ROLLBACK هنگام استفادهٔ دوباره از همان اتصال مشکل داشت. بررسی با اتصال تازه نشان داد دادهٔ نیمه‌کاره ثبت نشده است؛ برنامه نیز اتصال را در پایان درخواست می‌بندد. این محدودیت پنهان یا به‌عنوان موفقیت کامل پروتکل گزارش نشده است.

سه آزمونی که در محیط محلی اجرا نشدند، شامل دو ویرایش هم‌زمان، ایجاد هم‌زمان با یک شناسه و بازیابی همان اتصال پس از خطای SQL بودند. هر سه مورد همراه با بقیهٔ آزمون‌ها در GitHub Actions روی PostgreSQL 17 اجرا و موفق شدند.

## سابقهٔ GitHub Actions برای قدم سوم

- کد بررسی‌شده: [e860c02](https://github.com/sepehrebra/smart__planer/commit/e860c02ede46e4d5fee5e240fd10bd083832fbd5).
- **هر ۵۰ آزمون روی PostgreSQL 17 موفق بود؛ هیچ آزمونی skip نشد.**
- کانتینر پایگاه داده پس از ثبت دادهٔ آزمایشی دوباره راه‌اندازی شد؛ ورود به حساب و باقی‌ماندن کار ذخیره‌شده موفق بود.
- [اجرای شمارهٔ ۱ در GitHub Actions](https://github.com/sepehrebra/smart__planer/actions/runs/35431653192) با نتیجهٔ success پایان یافت.
- این نتیجه مربوط به آزمون‌های خودکار پایهٔ برنامه است؛ آزمون بار و بررسی انتشار عمومی همچنان باقی‌اند.

## بازبینی و اصلاح‌های پایه در قدم سوم

- ویرایش دادهٔ کامل دوباره اعتبارسنجی می‌شود و شرط نسخه/مالک در UPDATE نیز اعمال می‌شود.
- تلاش مجدد پس از حذف با نگه‌داشتن نشان حذف، کار را زنده نمی‌کند.
- پاسخ موفق پس از پایان تراکنش برمی‌گردد.
- مقدار نامعتبر رمز از جزئیات خطای FastAPI حذف شد؛ فاصله‌های رمز هنگام ورود حفظ می‌شوند.
- توکن CSRF نامعتبر پیش از مقایسهٔ امن از نظر قالب بررسی می‌شود.
- وضعیت 404 برای کار ناموجود و متعلق به کاربر دیگر یکسان است.

## کارهای باقی‌مانده

- قدم بعدی رابط کاربری و تقویم در فاز سوم است؛ سپس AI و خروجی فایل طبق ترتیب فایل اصلی.
- حذف/آرشیو برنامه، تغییر محدودهٔ برنامه، تقسیم کار بین دو برنامه و سیاست نگهداری رسیدهای قدیمی هنوز ارائه نمی‌شوند؛ محدودیت‌ها در راهنمای قدم پنجم ثبت شده‌اند.
- اجرای کامل Docker Compose در محیط دارای Docker هنوز بررسی نشده است.
- استقرار عمومی، بازیابی/تأیید ایمیل، پشتیبان‌گیری و بازیابی، نقش محدود پایگاه داده، محدودیت سراسری تلاش ورود و کنترل اندازهٔ بدنهٔ درخواست در پراکسی باید پیش از انتشار بررسی شوند. کنترل فعلی اندازه فقط Content-Length اعلام‌شده را بررسی می‌کند.
- حذف کار نرم است؛ سیاست نگهداری و حذف قطعی حساب/کار هنوز تصمیم نهایی ندارد.
- آزمون بار اجرا نشده و ظرفیت یا آماده‌بودن تجاری ادعا نمی‌شود.
- Starlette در آزمون با HTTPX هشدار مهاجرت آینده به HTTPX2 می‌دهد؛ اجرای آزمون فعلی موفق است و این هشدار خطای برنامه نیست.
